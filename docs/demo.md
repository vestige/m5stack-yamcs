# M5Sat デモのシナリオ（30分）

これからシステムを作る人に向けて、M5Sat で衛星運用の流れを見せるデモの台本です。システムの全体像は [overview.md](overview.md) にまとめています。デモの前半で、このページの図を見せながら説明します。

## ねらい

デモを見た人が、次のことを持ち帰れるようにします。

1. 衛星運用の登場人物（衛星バス・ペイロード・地上局・管制局）と、それぞれの仕事
2. 衛星と地上は、テレメトリとコマンドでしか話せないこと。そのために「届いたか」「実行されたか」を確かめる仕組みがいること
3. 衛星は地上から見えない時間も自分で動くこと（FDIR、予約した観測、パス）

## 時間配分

| 時間 | 場面 | 見せるもの |

| 0:00〜0:05 | 1. 全体像と役割 | overview.md の図、机の上の機材 |

| 0:16〜0:22 | 4. 異常と FDIR | GPS のケーブルを抜く → SAFE、アラーム、手順書で復旧 |

時間が押したら、場面 3 の観測データと、場面 5 の2回目のパスを省きます。場面 5 は、[scenarios.md の 5-9 の実験の結果](scenarios.md#s5-9) の画像で説明しても構いません。

## 準備

### 前日まで

- [ ] M5Stack（衛星）に最新のファームウェアを書き込む（`pio run -e m5stack-core-esp32 -t upload`）
- [ ] ESP-NOW で見せるなら、M5StickC（地上局）にも書き込む（`pio run -e ground-station -t upload`）。会場の Wi-Fi が使えるかわからないので、ESP-NOW をおすすめします
  - `.env` の `GROUND_STATION_SERIAL` に、M5StickC のシリアルポートを書いておく（`scripts/start.sh` が読む）
  - M5Stack の回線を ESP-NOW にしておく（C ボタンを2秒押すと切り替わり、再起動する。選んだ回線は電源を切っても残る）
- [ ] M5Stack と M5StickC を充電する
- [ ] 会場と同じ回線で、一度通しでリハーサルする。特に場面 4（ケーブルを抜く）と場面 5（パスの時刻）

## 1. 全体像と役割（0:00〜0:05）

**見せるもの**：タブ 1（overview.md の最初の図）と、机の上の機材を指さしながら。

**話すこと**

- 「M5Stack を人工衛星、Mac を地上の設備に見立てて、衛星の運用を模擬しています」
- 機材を1つずつ指さして、役割を言う

  | 指さすもの | 言うこと |
  | --- | --- |
  | M5Stack | 衛星バス。衛星の本体で、健康状態を報告し、コマンドを実行し、異常のときは自分で逃げる |
  | GPS ユニットとアンテナ | ペイロード。この衛星が打ち上げられた目的の観測機器。上空の GPS やみちびきの電波を受けて、信号の強さを観測する |
  | M5StickC | 地上局のアンテナと無線機。衛星と電波でやり取りする |
  | Mac の YAMCS | 管制局。衛星の状態を監視し、コマンドを送り、運用を計画する。YAMCS は本物の衛星にも使われている管制ソフト |

- 「GPS のアンテナは、衛星と地上局が話すためのアンテナではありません。衛星と地上局の通信は、M5Stack と M5StickC の中にある無線（ESP-NOW）です」
- 「衛星と地上は、テレメトリ（衛星から地上）とコマンド（地上から衛星）でしか話せません。今日はその流れを順に見ていきます」

## 2. 衛星の状態を見る（0:05〜0:10）

**見せるもの**：タブ 2（運用画面）→ タブ 3（Packets）→ タブ 4（Events）

| 操作 | 見せるところ | 話すこと |
| --- | --- | --- |
| タブ 2 を開く | 衛星の状態の区画 | 「これが運用者がパス中に見る画面です。HK（健康状態）が1秒ごとに届いています」 |
| | 運用モード（緑の NOMINAL）、ペイロード ON、FDIR ON | 「運用モードは色で見分けます。緑が NOMINAL、ふだんの状態です」 |
| | GNSS の区画 | 「ペイロードが測位できています。使っている衛星は○機」 |
| タブ 3 を開く | APID 100・101 が交互に届く | 「衛星から届いたパケットそのものです。CCSDS という宇宙機の標準の形式で、種類を APID という番号で見分けます」 |
| パケットを1つ開く | バイト列と、値に変換された一覧 | 「バイト列を、Mission Database の定義で『運用モード』などの値に変えています」 |
| M5Stack の電源ボタンを1回押して再起動する | タブ 4 に `BOOT` のイベント | 「衛星は、起きた出来事をイベントで知らせます。再起動の回数と理由がわかります」 |

M5Stack を再起動すると、運用画面の「再起動の回数」も1増え、「起動からの時間」が0に戻ります。

## 3. コマンドを送る（0:10〜0:16）

**見せるもの**：タブ 2（運用画面）→ タブ 5（Command history）→ タブ 6（Queues）

| 操作 | 見せるところ | 話すこと |
| --- | --- | --- |
| 運用画面の **NO_OP** を押し、確認ダイアログで OK | 受理した数が1増える。最後の ACK が `NO_OP` / `COMPLETED` | 「何もしないコマンドで、通信できることを確かめます。衛星が『受け取った』『実行した』と ACK を返してきます」 |
| タブ 5 を開き、いま送った NO_OP を開く | Queued → Released → Sent → Accepted → Completed の段階 | 「コマンドは送りっぱなしにしません。衛星から ACK が返ってきて、初めて『実行された』とわかります」 |
| 運用画面の **MODE MISSION** を押す | 運用モードが変わらない | 「運用モードを変える大事なコマンドは、すぐには送られません」 |
| タブ 6 を開き、待っているコマンドを承認（Accept） | 運用画面の運用モードが青の MISSION に | 「もう一人が承認して、初めて衛星へ送られます。二人確認です」 |
| 運用画面の観測の区画 | 捕捉している衛星、C/N0 が届き始める | 「MISSION になると、ペイロードの観測データが届きます」 |
| **MODE NOMINAL** を押し、タブ 6 で承認 | 緑の NOMINAL に戻る。約19秒後、観測データの値が紫に | 「紫は、値が届かなくなった（古い）ことを表します。MISSION をやめたので、観測データが来なくなりました」 |

時間があれば：運用画面の **PAYLOAD OFF** を押すと、GNSS の区画だけが紫になります。「どこが紫になったかで、何が止まったかがわかります」。見せたら **PAYLOAD ON** で戻します。

## 4. 異常と FDIR（0:16〜0:22）

**見せるもの**：M5Stack と GPS ユニット → タブ 2（運用画面）→ タブ 7（Alarms）→ タブ 4（Events）→ タブ 8（Stacks）

| 操作 | 見せるところ | 話すこと |
| --- | --- | --- |
| GPS ユニットのケーブルを M5Stack から抜く | | 「ペイロードが故障したことにします」 |
| 約10秒待つ | 運用モードが黄色の SAFE、ペイロード OFF | 「衛星が自分で異常に気づき、ペイロードを切って SAFE に逃げました。地上は何もしていません。これが FDIR です」 |
| さらに10秒ほど | GNSS の区画が紫に | 「ペイロードを切ったので、GNSS のデータはもう届きません」 |
| タブ 7 を開く | 運用モードのアラーム（SAFE） | 「運用者はアラームで気づきます」 |
| タブ 4 を開く | `FAULT_DETECTED`（GNSS のデータが届きません）、`MODE_CHANGED` | 「イベントで、何が起きたかを確かめます。原因の手がかりです」 |
| 運用画面の **PAYLOAD ON** を押す | 送られずに失敗する（Command history で送信の前提条件が NOK） | 「SAFE のときは、ペイロードを操作するコマンドを管制局で止めます。原因がわからないまま機器を入れ直さないためです」 |
| アラームを確認（Acknowledge）し、GPS のケーブルを挿し直す | | 「原因を確かめて取り除いてから、戻します」 |
| タブ 8 で `04-safe-recovery.ycs` を開き、実行する。`SET_MODE` で止まったらタブ 6 で承認 | 1行ずつ進む。NOMINAL に戻り、GNSS のデータが届く | 「復旧は、事前に確かめた手順書に沿って、1行ずつ確かめながら進めます。慌てやすい場面ほど、手順書が大事です」 |

`04-safe-recovery.ycs` は、最後に「再び退避していないか」を確かめるために少し待ちます。時間が押したら、NOMINAL に戻ったところで次へ進みます。

## 5. パス運用（0:22〜0:28）

**見せるもの**：ターミナル → タブ 9（Timeline）→ タブ 2（運用画面）→ M5Stack の画面

本物の衛星は、地上局から見える時間（パス）にしか通信できません。ここでは、3分ごとに1分間のパスを2回作ります。

| 操作 | 見せるところ | 話すこと |
| --- | --- | --- |
| ターミナルで `python3 tools/plan_passes.py create --passes 2 --interval 3 --duration 1 --start 0.5` | パスの時刻と、予約する観測の引数の表 | 「本物ではパスの時刻を軌道から計算します。今日は人工のパスを作ります」 |
| タブ 9 を再読み込みし、ビュー「パス運用」、**10 min** | パス・AOS/LOS・観測の予定の帯 | 「Timeline に、パスと、その間にする観測の計画が並びました」 |
| 約20秒待つ | 運用画面が紫に | 「今はパスの外です。地上からは衛星が見えません」 |
| ターミナルで、表の「観測 1」の引数で予約のコマンドを打っておく（まだ Enter は押さない）<br/>`python3 tools/send_command.py SCHEDULE_OBSERVATION Start=… Duration=… --approve` | | 「パスは短いので、送るものはパスの前に用意しておきます」 |
| パス1が始まる（運用画面の色が戻る）。すぐに Enter | Timeline の「通信の確認 1」が自動で走る。観測の状態が SCHEDULED | 「パスが始まると、通信の確認は自動で走ります。パスの間に、次のパスまでの観測を予約します」 |
| パス1が終わる | 運用画面が紫に。M5Stack の画面で MISSION になり、また NOMINAL に戻る | 「地上から見えない間に、衛星が予約どおり自分で観測しています」 |
| パス2が始まる | 運用画面の「最後の観測」が COMPLETED、始めた時刻が予定どおり | 「見えない間に起きたことは、次のパスで HK を見て確かめます」 |
| パス2のあと、`python3 tools/plan_passes.py clear` | データリンクが戻る | |

予約のコマンドがパス1に間に合わなかったら、そのまま場面 6 へ進み、[scenarios.md の 5-9 の実験の結果](scenarios.md#s5-9) の画像で説明します。

**話すこと**

## うまくいかないとき

| 症状 | 確かめること・対処 |
| --- | --- |
| 運用画面が全部紫のまま | `scripts/status.sh` で受信数が増えているか。増えていなければ、M5StickC の画面が `AOS` か、M5Stack が ESP-NOW の回線か（C ボタン長押しで切り替え）。Links でデータリンクが無効になっていないか（`python3 tools/plan_passes.py clear` で戻る） |
| コマンドが `no link available` で失敗する | パスの計画が残っていて、データリンクが止まっている。`python3 tools/plan_passes.py clear` |
| コマンドが Accepted で時間切れになる | 衛星に届いていない。M5StickC の画面と、`logs/udp_receiver.log` を見る |
| GNSS が測位できない（NoFix） | GPS のアンテナを窓際へ。屋内では時間がかかる。測位できなくても、場面 2〜4 は進められる（場面 4 は、ペイロードのデータ自体は届いていれば起きる） |
| ケーブルを抜いても SAFE にならない | FDIR が OFF になっていないか（運用画面の FDIR のランプ）。**FDIR ON** で戻す |
| `04-safe-recovery.ycs` が止まる | 承認待ち（タブ 6）か、GNSS のデータを待っている（ケーブルが挿さっているか） |
| 書き込みで `termios.error 22` | USB ケーブルを挿し直す |

デモのあとは、`python3 tools/plan_passes.py clear` で常時通信に戻し、`scripts/stop.sh` で止めます。
